# ParkGo — исправления

## Запуск и обновление

Рабочие файлы: `ParkGo/app.py` и `ParkGo/templates/index.html`. Файлы `index.html` вне templates и файлы с backup/old в имени — старые копии, Flask их не использует.

Если обновляете уже работающий проект, остановите сервер, сохраните копию вашей актуальной `parking.db` и обновите `app.py`, `templates/index.html` и `static/`. Не подменяйте вашу актуальную базу старой базой из архива. `secret.key` оставьте прежним.

Теперь база по умолчанию всегда находится рядом с app.py, независимо от папки запуска. Если раньше использовали базу из другой папки, укажите её абсолютный путь:

```bash
export PARKGO_DB=/полный/путь/к/вашей/parking.db
```

Две основные копии базы в полученном архиве (`parking.db` и `ParkGo/parking.db`) совпадали побайтно. Исходные базы в архиве сохранены без изменений; новые поля добавятся автоматически при запуске.

Для отдельного запуска распакованного проекта:

```bash
cd ParkGo
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Открыть http://127.0.0.1:5050. Быстрый запуск: `./start.sh`; инструкция: [README.md](README.md). Остановить сервер: Ctrl+C. Старую папку .venv из исходного архива переносить между компьютерами не требуется.

## Что изменено

Выбор места основан на оформлении `IMG-20261108-WA0007.jpg`: зелёные свободные места, красные занятые с машинками, жёлтые забронированные с замком, синий выбор и отдельная карточка бронирования. Для 1–4 мест используется компактный ряд, для больших парковок — два ряда с центральным проездом. После выбора парковки нажмите «Забронировать», выберите конкретное место на схеме и продолжите к форме. В бронь передаётся выбранное место. Если оно стало недоступно, сайт просит выбрать другое. Количество и номера мест соответствуют базе; дополнительные демонстрационные места в рабочую базу не добавляются.

«Поехать» и «Маршрут в 2ГИС» открывают маршрут на карте внутри ParkGo. Начало можно определить кнопкой «Моё местоположение» или указать кликом на карте. Для геолокации браузеру нужен HTTPS либо localhost и разрешение пользователя; при отказе остаётся выбор точки на карте. Построение выполняет официальный Directions plugin 2ГИС с существующим ключом проекта. При недоступности карты или маршрутизации показывается ошибка и ссылка на 2ГИС. Документация: https://docs.2gis.com/mapgl/map/tools/directions . Кнопка «Назад» возвращает к схеме с выбранным местом либо к подтверждению брони.

1. Подтверждение содержит кнопку «На карту / другая машина» и переход в «Мои брони». Можно бронировать разные свободные места для нескольких машин.
2. Кнопка статистики выводится только администратору. Серверная проверка /admin сохранена.
3. В английском интерфейсе цена остаётся в тенге и дополняется приблизительной суммой USD. Формула: тариф KZT / курс KZT за 1 USD, округление до двух знаков. Курс запрашивается сервером из датированного официального XML НБК, кэшируется на пять минут. Дата показана в интерфейсе, оплата остаётся в тенге. При недоступности НБК нет выдуманного курса: показывается сообщение USD estimate unavailable. Документация источника: https://nationalbank.kz/ru/page/rss ; адрес XML: https://nationalbank.kz/rss/get_rates.cfm?fdate=ДД.ММ.ГГГГ . Серверу нужен доступ к nationalbank.kz.
4. Экран загрузки закрывает появление элементов. Ожидает инициализацию карты, изображения и шрифты, с предельным ожиданием шесть секунд. При недоступности скрипта 2GIS остаётся схема парковок.
5. «Мои брони» загружаются из SQLite по ID авторизованного пользователя. Сохраняются машина, место, номер брони и срок. Последнее открытое подтверждение восстанавливается при обновлении страницы; если браузер запрещает localStorage, брони всё равно доступны через «Мои брони» после входа.

Срок новых броней хранится на сервере. Истёкшие брони освобождаются при следующем запросе; открытый сайт опрашивает сервер. Старые записи, для которых срок не сохранялся, показывают «До отмены»: их исходную длительность восстановить нельзя.

Добавлены транзакции для защиты от одновременного бронирования одного места, а также ключ повторного запроса при сетевом сбое. Ошибки отмены выводятся пользователю.

В старом шаблоне «QR-код» был случайным узором, а не настоящим QR. Он заменён номером брони и номером автомобиля. Интеграции со шлагбаумом в этом проекте нет.

## Проверки

Пройдено 4 автоматических серверных теста: несколько броней/перезагрузка/права/отмена; срок/истечение/старые брони/повтор запроса; одновременная бронь одного места; курс и недоступность источника.

```bash
python -m unittest discover -s tests -v
```

Также пройден интеграционный тест JavaScript в jsdom: навигация, вторая машина, перезагрузка подтверждения, список, отмена одной из двух броней, скрытие админ-кнопки, английская цена, завершение загрузки при недоступной карте. JavaScript-ошибок в этом сценарии не было. Курс в тесте подставной (500), только для проверки арифметики; в приложение он не записан.

Для JS-проверок нужен Node.js и изолированный сервер. Скрипт ниже создаёт временную базу и тестового пользователя test@astanait.edu.kz / test-password; рабочая база не используется. Не направляйте тесты на рабочий сервер.

```bash
.venv/bin/python tests/ui_server.py
```

Во втором терминале установите инструменты вне проекта и запустите проверки последовательно:

```bash
npm install --prefix /tmp/parkgo-tools jsdom playwright
NODE_PATH=/tmp/parkgo-tools/node_modules node tests/test_spot_selection.cjs
NODE_PATH=/tmp/parkgo-tools/node_modules node tests/test_availability.cjs
NODE_PATH=/tmp/parkgo-tools/node_modules node tests/test_ui.cjs
NODE_PATH=/tmp/parkgo-tools/node_modules node tests/test_routes.cjs
```

Playwright требует установленный Chromium (`/tmp/parkgo-tools/node_modules/.bin/playwright install chromium`). Для уже установленного браузера задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/путь/к/chrome`. Тест маршрутов обращается к настоящим сервисам 2ГИС и требует доступа в интернет. Для визуальной проверки схемы из 16 мест запустите тестовый сервер с `--reference-layout`; это влияет только на его временную базу.

Визуальная проверка выполнена в Chromium на экранах 1440×900 и 390×844. Реальный ответ Routing API и отображение маршрута внутри сайта подтверждены. Живой ответ сервиса НБК этим обновлением не проверялся; обработчики успеха и ошибки покрыты серверными тестами.

Повторная проверка занятости, компактной схемы и реальных координат парковок: [отчёт со скриншотами](artifacts/parking-review/README.md). Исправлены ответы опроса, приходящие в обратном порядке; бронь больше не изображается как стоящая машина. Все семь меток проверяются тестом на попадание в контуры парковок 2ГИС.

## Проверка регистрации и основных сценариев — 13 ноября 2026

Обнаружено и исправлено:

- Одна и та же ошибка скрывала отсутствие SMTP и сбой отправки. Теперь причины разделены, сообщения переведены RU/EN, для администратора есть `./start.sh check-mail` и пример локального `.env`.
- SMTP всегда использовал STARTTLS, поэтому SSL-подключение на порту 465 не работало. Добавлены оба режима с проверкой сертификатов.
- Ссылки за обратным прокси могли использовать внутренний адрес или HTTP. `PARKGO_PUBLIC_URL` задаёт публичный адрес для писем без доверия произвольным forwarded-заголовкам.
- Ссылка регистрации содержала подписанные, но не зашифрованные данные, включая хеш пароля. Теперь ссылка содержит случайный одноразовый токен; его хеш и регистрационные данные сохраняются в отдельной таблице до подтверждения. Срок — один час. Старые ссылки необходимо запросить заново.
- После ошибки форма теряла имя и почту; успешная отправка письма показывалась красным сообщением. Исправлены сохранение полей, цвет/роль уведомления и заголовок вкладки регистрации. Пароль повторно в HTML не выводится.
- Заблокированное localStorage/sessionStorage или неизвестное значение языка ломали страницу входа/админку. Добавлены обработка отказа хранилища и запасной русский язык.
- После успешного входа оставались предыдущие неудачные попытки. Счётчик теперь сбрасывается при успешной проверке пароля.
- Обратная косая черта в `next` могла дать перенаправление на внешний сайт. Такие адреса и управляющие символы отклоняются.
- Не-ASCII токены CSRF/датчика и JSON-массив вместо объекта могли вызывать 500. Теперь возвращаются клиентские ошибки 403/401/400.
- Чтение статуса и обновление датчиком не были одной транзакцией, что позволяло конфликт с бронированием. Теперь используется блокировка записи до чтения; добавлен тест конкурентных запросов.
- Админка не проверяла результат отмены/закрытия обращения и скрывала сбои перезагрузкой. Теперь показывается ошибка и можно повторить действие. Несуществующее обращение возвращает 404.

Дополнительно доступен явно включаемый `PARKGO_REGISTRATION_MODE=demo` для учебного запуска без SMTP. Этот режим не проверяет владение почтой; форма сообщает об этом. По умолчанию остаётся `verified`. При сбое почты сайт не переключается в demo автоматически.

Проверки выполняются на временных базах, без отправки реальных писем:

```bash
.venv/bin/python -m unittest discover -s tests -v
# В отдельном терминале, без SMTP-переменных:
.venv/bin/python tests/ui_server.py --admin-user
# Требуется jsdom:
node tests/test_auth_ui.cjs
node tests/test_ui.cjs
node tests/test_availability.cjs
node tests/test_spot_selection.cjs
```

Проверены конфигурация SMTP, имитация отправки/ошибки, подтверждение/истечение/повтор ссылки, явный demo-режим, вход, доступы, конкурентное бронирование, промокоды, QR, датчики, админка и интерфейсные сценарии. Это не подтверждение доставки реального письма или работы публичного сервера: для них нужны настройки и проверка на хосте пользователя. Инструкция по включению регистрации приведена в README.
